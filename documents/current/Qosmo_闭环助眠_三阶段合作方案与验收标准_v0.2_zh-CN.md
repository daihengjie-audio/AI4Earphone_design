# Qosmo 闭环助眠三阶段合作方案与验收标准 v0.2

**用途：** 合作合同/SOW 编制与阶段验收  
**合作范围：** Qosmo 负责根据睡眠状态及生理特征，完成助眠音频策略、实时生成/编排、播放控制与效果验证；脑电采集、睡眠分期及慢波相位识别由甲方或其他合作方提供。

---

## 阶段一：整体方案设计

【阶段一时间】  
2个月

【工作描述】

1. 聚焦睡眠质量改善，从产业界、学术界对声音助眠及音频闭环调控技术进行调研、分析与总结。重点研究不同声音类型及音乐特征对入睡、睡眠分期、脑电、心率/心率变异性等指标的影响，梳理技术原理、适用场景、有效性证据及局限。
2. 聚焦实时闭环助眠，设计“睡眠状态/生理特征输入—调控策略—音乐参数—音频输出—效果反馈”的整体技术方案。方案应明确输入信号、状态到音乐的映射规则、触发/保持/切换/停止逻辑、异常回退及效果评价方法。
3. 对实时自由生成、受约束生成、音乐库检索与实时编排等技术路线进行比较和选型，明确主方案、备选方案、部署方式、软硬件模块及规格参数要求。
4. 完成技术可行性验证设计，明确阶段二原型的系统架构、接口、性能指标、测试方法及阶段三人体效果验证方案。

【交付件】

1. 《声音助眠及音频闭环调控技术分析报告》1份。
2. 《Qosmo闭环助眠系统整体技术方案》1份。
3. 《原型系统选型、参数规格及验证方案》1份。

【验收标准】

1. 《声音助眠及音频闭环调控技术分析报告》应包含：
   1）主要声音助眠技术的方案、调控原理及适用睡眠场景；  
   2）有效性证据，包括实验方案、对照条件、测试人群类型与数量、睡眠及生理指标、主要结果与证据局限；  
   3）不同声音类型及关键音乐特征对脑电、心率/心率变异性、入睡和睡眠结构的可能影响；  
   4）各技术路线的优势、劣势、风险及产品化成熟度；  
   5）调控效果评价指标与评价方法。
2. 《Qosmo闭环助眠系统整体技术方案》应包含：
   1）系统目标、目标人群、使用场景及合作边界；  
   2）端到端系统架构、各模块功能、数据流和控制流；  
   3）睡眠状态/生理特征输入要求，包括字段、时间戳、更新频率、信号质量和置信度要求；  
   4）状态到音乐参数的映射原则，以及触发、保持、切换、渐弱、停止和安全回退逻辑；  
   5）音乐生成/检索/编排方案，以及音量、速度、音色、复杂度、连续性等参数的控制原则；  
   6）日志、版本管理、离线回放、异常处理及用户主动停止机制。
3. 《原型系统选型、参数规格及验证方案》应包含：
   1）实时自由生成、受约束生成、音乐库检索与实时编排等路线的比较依据及选型结论；  
   2）主方案和可直接启用的备选方案；  
   3）原型软硬件选型、核心模块、接口、部署方式及第三方依赖；  
   4）状态更新周期、策略计算时延、音频响应时延、连续运行、音频输出及安全边界等规格要求；  
   5）阶段二测试用例、评价指标和通过阈值；  
   6）阶段三测试人群、对照条件、主要/次要终点、样本量和统计分析原则；  
   7）代码、模型、音乐内容、输出音频、研究数据及新增知识产权的归属和使用边界。
4. 三份报告内容应相互一致，需求、模块、参数和验收指标可逐项追溯；未明确主方案、备选方案、量化规格或知识产权边界，不通过阶段验收。

## 阶段二：原型系统搭建

【阶段二时间】  
3个月

【工作描述】

1. 按阶段一冻结的总体方案搭建闭环助眠原型，完成睡眠状态/生理特征输入、策略判断、音乐生成或编排、音频播放控制、日志记录及离线回放的全链路集成。
2. 实现状态到音乐参数的实时映射，以及触发、保持、切换、渐入渐出、停止和安全回退功能；在信号质量不足、状态未知、输入中断或系统异常时，不新增刺激并回退至安全状态。
3. 使用模拟数据和已记录生理数据开展接口、功能、时延、稳定性、异常注入、音乐连续性和参数命中测试。
4. 完成原型部署、使用、测试及移交材料，为阶段三人体效果验证提供冻结版本。

【交付件】

1. Qosmo闭环助眠原型系统1套。
2. 《原型系统技术设计及接口说明》1份。
3. 《原型系统工程测试报告》1份。
4. 原型系统交付包1套，包括约定范围内的软件、模型/策略配置、音乐内容包、部署文件、测试工具和使用手册。

【验收标准】

1. Qosmo闭环助眠原型系统应实现：
   1）接收阶段一约定的睡眠状态、生理特征、信号质量、置信度及时间戳；  
   2）根据输入状态实时选择或调整音乐策略及音乐参数；  
   3）完成生成/检索/编排、播放、渐入渐出、停止和安全回退；  
   4）完整记录输入、策略判断、实际音乐参数、播放事件、异常及软件/模型/内容版本；  
   5）按统一时间轴离线回放并复现每次闭环决策；  
   6）支持用户主动停止及甲方约定的安全限制。
2. 《原型系统技术设计及接口说明》应包含系统架构、各模块功能、接口字段、状态机、音乐参数、时序、异常码、部署环境、依赖清单及版本管理方法。
3. 《原型系统工程测试报告》应包含：
   1）阶段一全部测试用例的逐项结果、原始记录、缺陷和整改情况；  
   2）端到端时延、策略/参数命中率、连续运行时长、异常回退成功率、日志完整率等指标；  
   3）音乐连续性、自然度、入睡适配度及异常声音的主客观评价；  
   4）输入丢失、延迟、乱序、低信号质量、状态未知、网络/服务中断和播放中断等异常测试结果。
4. 原型性能应达到阶段一冻结的阈值；建议最低要求为：
   1）强制功能实现率100%；  
   2）安全回退成功率100%，安全相关错误刺激为0；  
   3）输入、决策、输出和版本的日志完整率100%；  
   4）策略计算时延P95不高于500 ms，可听音乐变化不晚于1个音乐小节；  
   5）连续运行不少于8小时，无崩溃、状态机死锁或不可回放事件；  
   6）阻断级缺陷为0。
5. 甲方应能在约定环境中依据交付包独立部署、运行和复现测试结果；仅能由Qosmo现场演示、不能独立部署或回放，不通过阶段验收。

## 阶段三：效果验证

【阶段三时间】  
4个月；伦理审批、受试者招募时间另行确认。

【工作描述】

1. 在人体试验前开展影子运行：系统读取真实睡眠/生理输入并产生决策，但不实际播放自适应变化，用于验证决策正确性、时延、错误触发、信号质量门控和安全回退。
2. 开展随机对照人体试验，验证闭环助眠系统的安全性、可用性及相对开环音频的增量效果。建议至少设置：固定优选音频、个体化开环音频、实时生理耦合闭环音频；如条件允许，增加无声或伪刺激对照。
3. 评价入睡、睡眠结构、脑电及自主神经生理变化、主观睡眠质量、声音接受度、打扰/觉醒、摘除/停止和持续使用意愿。
4. 分析闭环系统的适用人群、适用睡眠阶段、有效策略、无效或高风险场景，并提出产品化、收窄使用范围、回退开环或停止开发的建议。

【交付件】

1. 《闭环助眠人体效果验证方案》1份。
2. 《影子运行及系统正确性验证报告》1份。
3. 《闭环助眠效果验证报告》1份。
4. 人体研究数据及事件日志包1套。
5. 《产品化建议及最终技术移交报告》1份。

【验收标准】

1. 《闭环助眠人体效果验证方案》应包含：
   1）研究目的、测试人群、纳入/排除标准、样本量依据及退出规则；  
   2）随机、对照、盲法、测试周期及条件顺序；  
   3）唯一主要终点、次要终点、机制指标、安全指标及最小产品意义阈值；  
   4）数据采集、质量控制、缺失数据、多重比较及统计分析方法；  
   5）冻结的软件、模型、策略、音乐内容、设备及配置版本。
2. 《影子运行及系统正确性验证报告》应证明：
   1）系统仅在有效信号质量、允许状态和安全窗口内产生闭环决策；  
   2）决策、实际播放、停止和异常均可按统一时间轴复现；  
   3）错误触发、时延、状态漂移、输入中断和回退均有完整记录；  
   4）安全相关错误刺激为0，达到人体播放验证的启动条件。
3. 《闭环助眠效果验证报告》应包含：
   1）各对照条件的入睡、睡眠结构、脑电/自主神经生理、主观体验、安全和可用性结果；  
   2）闭环音频相对个体化开环音频的差异、效应量、置信区间、个体差异和跨夜变异；  
   3）脱落、缺失、顺序效应、残留效应及敏感性分析；  
   4）响应者、无效者、易受打扰人群及适用策略分析；  
   5）全部预设终点的结果，不得只选择性报告正向结果。
4. 人体研究数据及事件日志包应包含去标识数据、数据字典、质控记录，以及能够逐夜对齐的输入状态、闭环决策、实际播放和版本信息，数据完整性达到研究方案预设标准。
5. 阶段三的合同验收以“研究按冻结方案合规完成、数据完整、分析可复核、报告真实完整”为准，不以必须得到正向疗效结果为前提；效果结果用于产品决策：
   1）闭环相对个体化开环达到预设最小产品意义阈值，且无不可接受的安全或打扰风险：建议进入产品化；  
   2）声音或个体化有效，但闭环无增量：回退至固定/个体化开环方案；  
   3）仅特定人群有效：收窄人群和策略后再验证；  
   4）无睡眠价值或安全、打扰风险不可接受：停止该路线。

## 合同中建议明确的共同条款

1. 每阶段验收对象均应冻结软件、模型、策略、音乐内容、设备及配置版本。
2. 阶段付款与交付件完整性、量化验收结果、关键缺陷关闭及知识产权清晰度绑定。
3. 明确背景知识产权、新增知识产权、代码、模型、音乐内容、输出音频、研究数据和发表/宣传权。
4. Qosmo应披露第三方模型、训练/参考内容、云服务和许可限制，不得依赖不可转授权内容或个人账号完成交付。
5. 未通过验收时，应按约定执行整改、收窄范围、启用备选方案或终止，不自动进入下一阶段。
